# 2026.242.2251 — feat(beds): port upstream's system and cups acceptance suites

## Summary

The first two suites of upstream Omarchy's acceptance corpus
(`omacom/omarchy@quattro` `test/acceptance.d/`) ported onto `check-omarchy-iso-vm`:
**`system-test.sh`** and **`cups-test.sh`**. The bed goes from 28 to 52 steps.

Every assertion is a typed verb. Where upstream groups its checks into five bash functions
(`verify_core_packages` / `_defaults` / `_services` / `_runtime_tools` / `_user_setup`) and
fails the whole group at its first bad line, each is one step here — so a failure names the
exact fact that is wrong rather than the group it lived in.

This is the first consumer of the four verb fields that merged today:

| assertion | verb |
|---|---|
| pipewire / wireplumber are running **in the user session** | `service: {scope: user, running: true}` |
| no unit is failed, on **either** manager | `service: {none_failed: true}` (+ `scope: user`) |
| the desktop user is **not** in the root-equivalent docker group | `user: {not_groups: [docker]}` |
| the CUPS policy file is `root:cups 0640` | `file: {owner, group_of, mode}` |
| the docker daemon is unreachable; `lpinfo -v` is denied | `command: {expect_non_zero: true}` |

`none_failed:` deliberately carries **no `ignore:` regex**. Upstream offers one for dev
machines; on a freshly installed VM the moment an ignore is needed, that is a finding rather
than a configuration detail.

## Seven assertions the first run rejected — and why the guest was right both times

The first run was 51 pass / 7 fail. Neither cluster was a defect in the guest.

### Six: the test suite is newer than the artifact under test

Upstream's `cups-test.sh` asserts `cups-pdf`, `cups-browsed` and unauthenticated
`lpinfo -v` are all **absent**. None of that holds on this bed, and 4.0.1 is correct:

```
$ grep -E cups /usr/share/omarchy/install/omarchy-base.packages     # on the guest
cups
cups-browsed
cups-filters
cups-pdf
```

no `cups-pk-helper`, and `install/post-install/pacman.sh` **configures** cups-browsed
(copies `etc-overrides/cups-cups-browsed.conf` into `/etc/cups`) rather than removing it.
Omarchy's CUPS hardening landed **after** 4.0.1; this bed pins `omarchy-4.0.1.iso`.

So the five hardening assertions are held back, with the version boundary and its evidence
recorded in place. They belong here the moment `source.url` moves to a release carrying the
hardening — at which point they become a genuine regression gate for that upgrade, rather
than a bed that fails on a correct system today.

What replaces them is what 4.0.1 itself guarantees: `cups` and `cups-filters` installed,
`cups.service` enabled and running, and the policy file's ownership and mode.

### One: reproducing upstream faithfully would have reproduced a vacuous check

Upstream asserts `[[ -d $(xdg-user-dir DOCUMENTS) ]]`. On this guest
`~/.config/user-dirs.dirs` defines only `XDG_DESKTOP_DIR="$HOME/"`, so `xdg-user-dir` falls
back to `$HOME` — which is a directory — and **upstream's own check passes without
`~/Documents` existing**. Measured: `~/Downloads` and `~/Pictures` are real, `~/Documents`
and `~/Desktop` are not.

The port asserts the two that exist, and says why the other two are not asserted. Copying
the upstream form would have meant shipping a check that tests nothing.

## Rulebook compliance

- **R1 — RCA every anomaly.** All seven failures were root-caused on the live guest — to a
  version boundary and to a fallback in `xdg-user-dir` — before any assertion was touched.
  Neither was allowlisted, loosened to pass, or blamed on the guest.
- **R2 — No pre-existing / out-of-scope split.** Nothing parked. The five withheld
  assertions are not deferred work: they describe a different release, and the condition
  for their return (`source.url` moving past the hardening) is named in the file.
- **R3 — No duplication.** Assertions land on existing shared verbs; nothing reimplemented.
- **R4 — No workarounds.** No sleeps; `eventually:` is the only wait, used on the unit
  sweeps and the user-session services which settle after boot.
- **R4a — Fix the product first.** No product change was needed — the four verbs this
  consumes shipped in their own repos first.
- **R5 — Delete legacy completely.** N/A — additive to the bed.
- **R6 — Git safety.** `git status` inspected; branched from a fresh `origin/main`; no
  force-push, no direct push to `main`, no hook bypass.
- **R7 — Prove the gate, not the plan.** The full R10 sequence is pasted above verbatim.
- **R9 — Binary equals source.** Every result is from a `task build:binary` charly carrying
  the merged verb pins (charly#498).
- **R10 — Fresh disposable proof.** `check-omarchy-iso-vm` is `disposable: true`; the
  post-rebuild assertion count is the one that counts.
