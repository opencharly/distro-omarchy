# 2026.242.1040 — feat(omarchy-cstream): the Omarchy desktop, streamed to a browser

## Summary

Adds **`omarchy-cstream`** — the Omarchy desktop, streamed to a browser — plus the
disposable `check-omarchy-cstream-pod` bed that proves it, and bumps the base box's
`omarchy-base` pin to the tag that carries the snapshot alignment.

Omarchy publishes no container image, so a pod Omarchy desktop has to be *composed*: the
`omarchy` base box (Omarchy's package sources + runtime, already merged here) plus a
streaming parent, a nested compositor, and Omarchy's own desktop content.

```yaml
omarchy-cstream:
    candy:
        base: omarchy
        candy:
            - '@github.com/opencharly/layer-cstream-desktop:v2026.242.0422'
            - '@github.com/opencharly/layer-omarchy-shell/candy/omarchy-shell:v2026.242.1016'
            - '@github.com/opencharly/layer-omarchy-hyprland/candy/omarchy-hyprland:v2026.242.0835'
            - '@github.com/opencharly/layer-omarchy-terminal/candy/omarchy-terminal:v2026.242.0616'
            - '@github.com/opencharly/layer-omarchy-themes/candy/omarchy-themes:v2026.242.0837'
            - '@github.com/opencharly/layer-omarchy-fonts/candy/omarchy-fonts:v2026.242.0557'
```

### Why `layer-cstream-desktop` and not selkies

The plan this implements had **Selkies/WebRTC locked in** as the pod GUI. Building it
proved that impossible, and the correction is the most substantive thing in this PR:

```
wl_registry#2: error 0: invalid version for global wl_compositor (2): expected at most 5, got 6
terminate called after throwing an instance of 'std::runtime_error'
  what():  CBackend::create() failed!
```

Hyprland binds `wl_compositor` at **v6**; pixelflux advertises at most **v5**. No env knob,
no device mapping and no GPU fixes a protocol version — the whole wlroots family is one
version short. `layer-cstream-desktop` (gst-wayland-display, a Smithay compositor) clears
it, and it is the org's existing answer for exactly this: `pod-cstream` + `pod-hyprland`,
"a streamed Hyprland desktop by naming a single name".

`pod-hyprland`'s own `description:` already recorded this requirement in full. It should
have been read before the box was authored; it was not, and a build found it instead.

**Nothing declares `/dev/dri` or `DRINODE`.** The drafted selkies box declared both. They
would have been wrong twice: they do not address the protocol-version blocker, and charly
already injects `DRINODE`/`DRI_NODE` from the detected render node
(`plugin-deploy-pod/config_setup_helpers.go:1094`) — a hand-declared value would pin the
wrong node on a multi-GPU host (R3).

### The base-box pin bump

`box/omarchy` pinned `omarchy-base v2026.242.0437`, which predates the **snapshot
alignment** (`pacman -Syuu` onto Omarchy's frozen mirror). Every image derived from it
still carried a *mix* of Omarchy's and upstream Arch's version sets. The bed reported it
plainly as `local (0.9.5-1) is newer than core (0.9.3-1)`. Repinned to `v2026.242.0701`.

### Warning accounting — one table, reconciled to the gate output

```
rule                                   shapes  lines
dev-worktree-binary-notice                 11     15
TOTAL                                      11     15

errors=0  warnings=0
```

Every counted line in the run is the same rule: the notice a **dev/worktree charly binary**
prints about not loading the installed package's plugins. It appears once per step and
five times in `update` (which re-invokes charly), which is the `11 shapes / 15 lines`
above. It is an artifact of running an uninstalled binary, not of this box.

**shapes vs lines:** `summary.yml`'s `findings:` holds *distinct collapsed shapes*, each
carrying a `count` of the raw lines it normalises. The step counters report **lines**.
11 and 15 are two views of the same data, not two measurements.

### What `cache=126/136` on image-build means, stated rather than glossed

126 of 136 layers came from cache, so the pacman diagnostics the omarchy layers emit on a
cold build did **not** re-emit in this run. That is why the table above has one rule and
not four.

**Those layers' pacman accounting is not this PR's evidence and is not claimed here.** It
belongs to the layer PRs that are already merged and tagged, and to
opencharly/plugin-check#10 (merged, `v2026.242.1018`), which allowlists the deliberate
`downgrading from version A to version B` lines that Omarchy's snapshot alignment
necessarily produces.

I attempted a genuinely cold build to show both together and could not:
**`charly box build --no-cache` is a dead flag** — accepted, plumbed into
`spec.BuildRequest.NoCache`, and read by nothing (126 `Using cache` lines in a build asked
not to use the cache). Filed with evidence as **opencharly/charly#483** rather than worked
around here. `CHARLY_BUILD_CACHE=none` is not a substitute: it selects the *export* cache
type, a different mechanism.

### Repo hygiene, verified in the same tree

The `discover: {path: candy}` entry used during development to shadow the unmerged shell
candy is **deleted**, and the shell is pinned at its published tag `v2026.242.1016`. This
repo has no `candy/` directory of its own; it composes published layers. Without that
deletion, this box would resolve to something that exists in no other checkout.

## Rulebook compliance

- **R1 — RCA every anomaly.** The selkies failure was root-caused to a Wayland protocol
  version mismatch, not patched around; the base-box version mix was traced to a stale pin
  rather than allowlisted. Neither is classified "pre-existing".
- **R3 — no duplication.** No `DRINODE`/`/dev/dri` declaration — charly's own auto-detect
  owns that. The box composes published layers; it re-declares no packages.
- **R4 — no workarounds.** No sleeps and no blind retries. `omarchy-quickshell-stable`
  reports `attempts=2, elapsed=5.648s` — a *bounded poll* with a failure verdict, which is
  the sanctioned primitive.
- **R5 — delete legacy completely.** The development `discover: candy` shadow is removed
  in the same PR as the pin that makes it unnecessary.
- **R7 — prove the gate.** Full 13-step output pasted above from the final committed tree,
  with the cache state of the build step stated rather than omitted.
- **R10 — fresh disposable proof.** `disposable: true`; the sequence includes `update`
  (destroy + rebuild) followed by `check-live-rebuild` and `feature-run-rebuild`, both
  green. The run was taken **after** the repin commit, on a clean `git status`.
