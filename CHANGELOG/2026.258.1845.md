# 2026.258.1845 — test(bed): exercise wl focus/fullscreen/minimize by bare target, not just close

## Summary

The `check-omarchy-desktop-vm` bed authored only ONE of the four Hyprland window verbs
(`wl: close`). `candy/plugin-wl` (opencharly/plugin-wl#18) routes all four
(`focus`/`close`/`fullscreen`/`minimize`) through ONE bare→`class:` selector normalization and
makes the dispatch CHECKED, and a regression there — `wlFocus` keeping its raw target while the
actions normalized — was invisible to a bed that never authored `wl: focus`.

This adds bare-target coverage for `focus`, `fullscreen`, and `minimize`, each paired with an
observation, plus a NEGATIVE step for the new checked-dispatch failure path:

- `wl: focus target: foot` — the PASS is the observation: the plugin's dispatch is now
  CHECKED, so a bare target that did not normalize to a matching selector would make
  `hyprctl` print `hl.focus: window not found` and the verb would FAIL;
- `wl: fullscreen target: foot` → `fullscreen == 1` asserted, then toggled back off;
- `wl: minimize target: foot` → the window lands on `special:minimized` (asserted);
- `wl: focus target: this-window-does-not-exist-xyzzy` → **exit_status: 1** (the checked
  dispatch FAILS on an unresolvable selector — pre-fix it exited 0 and reported success).

All use a **bare** target (the shape every bed authors and the shape the wlrctl backend matches
as the app id). The state assertions export the Hyprland env first (these `command:` steps are
not login shells — the cachyos-bed precedent).

## Cross-repo landing order (the dependency this PR carries)

The negative step (`exit_status: 1`) asserts behavior that **only exists in
opencharly/plugin-wl#18** (the CHECKED dispatch). The bed's plugin-wl ref is
`@github.com/opencharly/plugin-wl/candy/plugin-wl:v2026.244.0851` (`charly.yml:87`) — the
PRE-fix tag — so **against the default pin this bed's negative step would get exit 0 and
FAIL.** This PR is therefore ordered AFTER plugin-wl#18:

1. **opencharly/plugin-wl#18** merges and `tag-on-merge` mints its CalVer tag (its 4 substantive

   lane, or a one-line pin commit on this branch — see the note below).
