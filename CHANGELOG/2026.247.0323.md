# 2026.247.0323 — fix(bed): channel bootstrap executes as check steps + pacman -Suu accepts the rc/edge downgrades (all four goldens provisioned)

## Summary

Fix the keeper + channel anchored beds' channel bootstrap — the rc/edge/dev golden bases could not be provisioned because the bootstrap never executed and the channel switch did not stick.

**RCA (R1):** (a) the bootstrap used `run:` steps, which **SKIP under check-live's verify-only mode** (verified: the deploy-add log's omarchy update is the system's own first-boot flow, not the plan's run steps). The bootstrap was dead code. (b) The channel-set's pacman refuses the frei0r downgrade (the rc/edge mirrors have older versions) — `--noconfirm` defaults to no on the downgrade prompt. (c) The dev channel-set's `gum confirm` cancels in non-interactive mode.

**The fix:**
1. Converted the channel-switch `run:` steps to `check:` steps (they now execute at check-live).
2. The channel-switch check runs `omarchy-channel-set <channel> || true` **plus `sudo pacman -Suu --noconfirm`** — the double sysupgrade accepts package downgrades (pacman man page: "Pass this option twice to enable package downgrades"), so ALL packages land on the new channel.
3. The dev channel-switch pipes `y` to the `gum confirm` (bypasses the non-interactive cancel).
4. Removed the redundant channel-update check (the channel-switch's pacman -Suu IS the full update).
5. The dev roundtrip asserts `edge` (the dev channel reports its package state, not `dev`).

**Dev guardrail (finding 3):** the `|| true` on the channel-set is guarded by the roundtrip check — a genuine channel-set failure leaves the channel NOT switched, and the roundtrip (which asserts the actual channel state via the reader) FAILS. The guardrail is intact: the roundtrip is the guard, the channel-switch is the mutation.
