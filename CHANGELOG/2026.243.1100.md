# 2026.243.1100 — feat(beds): port omarchy's five GUI acceptance suites

## Summary
check-omarchy-desktop-vm proved the desktop COMES UP - a session, a shell, a bar. It did not
prove the desktop WORKS. Upstream omarchy ships nine acceptance suites; system and cups were
ported in #8. This ports the five GUI ones - session, apps, menu, panels, shell-surfaces -
taking the bed from 16 steps to 99.

Every assertion is a typed check verb. No bash.

## What each suite proves

  session          the rest of upstream's session facts: all 13 core shell plugins loaded,
                   the audio stack up, omarchy-version answering, and NO FAILED UNITS in
                   system OR user scope - upstream's strongest whole-machine assertion,
                   reachable because plugin-service#5 added scope: user and none_failed:
  apps             launch a terminal and the writer, prove a window maps, close it, prove the
                   window is gone - each guarded by a pre-existing-window check, which is
                   what makes the "opens" assertion mean anything
  menu             the root menu opens, maps, and closes on Escape
  panels           every bar panel (weather, bluetooth, network, audio, monitor) opens and
                   closes on its shared omarchy-keyboard-panel surface, plus the Tab
                   navigation contract, the single-monitor no-dismissal-twin invariant, and
                   the no-battery path for power
  shell-surfaces   seven flows: emoji picker, clipboard round-trip, system menu, background
                   and theme selectors, the reminder flow, notifications, and the apps-menu
                   launcher loop

## What is NOT ported, and why

NINE assertions across three suites need OCR - upstream's screen_contains, which reads text
off a screenshot. They are named per-suite in the file. That is `artifact_contains_text:` as
a fifth artifact modifier beside artifact_min_bytes/_min_dimensions/_not_uniform, and it is
its own cutover: it touches spec + sdk and needs an OCR engine on the HOST.

The menu suite loses more than its two screen_contains. Upstream walks thirteen keypresses to
the bar-position setting and asserts the bar turns vertical, verifying every intermediate
screen with OCR - because a blind key sequence only means something if you can see where it
landed. Ported blind it would be guesswork against a layout this bed cannot observe, and
against a DIFFERENT layout than upstream's: the guest is omarchy 4.0.1, the suite is read at
quattro. A sequence tuned to quattro that lands elsewhere on 4.0.1 fails while the desktop is
perfectly correct. The other suites port faithfully because they are SEARCH-driven - type a
name, take the top hit - which does not depend on layout.

## Two things upstream does that a disposable bed does not need

State restore: upstream saves and restores weather.json, shell.json and bar visibility with
trap handlers because it reuses a machine. This bed is disposable: [update] destroys the guest
and rebuilds it, so the destroy IS the restore. The one exception is the menu suite's config
reset, which is done inline because later steps in the SAME run assert against a default bar.

Hardware branching: upstream branches on `upower -e` for the power panel. A libvirt guest
deterministically has no battery, so the branch collapses to its else arm - which is the arm
worth pinning, because a power panel APPEARING on a machine with no battery is the defect.

## Defects this port surfaced, both fixed at cause

plugin-wl#9 - `wl: exec` never returned for the apps it exists to launch. It backgrounded the
job but the child inherited stdout/stderr, so the capture pipe never reached EOF and the verb
blocked for its whole deadline. The app launched, mapped and closed correctly; only the verb
that started it reported failure. `wl: clipboard set` had the identical defect, because
wl-copy stays alive to own the selection. The bed pin moves to v2026.243.1001 for both.

Verb choice: the bar toggles were `wl: exec` and are now `command:`. exec detaches and
redirects to /dev/null - right for a GUI app that never exits, wrong for a fast state change
whose exit status IS the assertion. Run as exec the toggle silently did not land and the
failure surfaced two steps later, against a bar still parked off-screen.

OMARCHY_PATH is prefixed per-command rather than hoisted to a deploy-level env:. That hoist
was tried and measured: env: is the DEPLOY's environment, not a check-step environment, and it
left 35 steps failing where 8 had. The repetition is the working form.

## Rulebook compliance

- **R1 — RCA every anomaly.** Four bed runs, and every failure was root-caused rather than
  tuned away. `wl: exec` timing out was fixed in the VERB (plugin-wl#9), not by widening
  `eventually:`. The bar-reveal failure was traced to the wrong verb choice, not declared flaky.
  The 62/35 regression was traced to my own change and reverted with the reason recorded in the
  file.
- **R2 — Nothing parked.** The nine OCR-gated assertions are not deferred work being hidden:
  they are named per-suite in `charly.yml` with what unlocks them (`artifact_contains_text:`,
  which touches spec + sdk and needs a host OCR engine — its own cutover). Every defect this
  port surfaced was fixed at cause in the same push, including a version split I caused by
  moving this bed ahead of its chain.
- **R3 — No duplication.** The suites reuse the existing verbs; `hypr-layers`' computed
  on/off-screen verdict is what makes the bar and panel assertions possible without
  reimplementing geometry per step.
- **R4 — No workarounds.** No sleeps and no blind retries — waiting is `eventually:` +
  `retry_interval:`. The `OMARCHY_PATH` prefix is repeated per command because the DRY
  alternative was tried, measured, and does not work; the measurement is in the file so the
  next reader does not retry it.
- **R5 — Delete legacy completely.** The stale comment describing the bar toggles as `wl: exec`
  was corrected when the verb changed, rather than left describing code that no longer exists.
- **R6 — Git safety.** Branched from a fresh `origin/main`; no force-push, no hook bypass, no
  direct push to main.
- **R7 — Prove behavior, not compilation.** Full R10 pasted above, run WITHOUT a repo override
  so the evidence comes from the pinned tag rather than a local checkout.
- **R10 — Fresh disposable proof.** `check-omarchy-desktop-vm` is `disposable: true`;
  `[update]` destroys the guest and rebuilds it, and `check-live-rebuild` re-runs every
  assertion against the rebuilt guest.
