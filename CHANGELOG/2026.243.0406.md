# 2026.243.0406 — refactor(beds): the pacstrap bed asserts through typed verbs

## Summary

The conversion withdrawn from #8, now that the bed can actually run. It goes from 5
`command:` shell steps to 1.

  grep '^ID=' /etc/os-release    ->  file: {contains: 'ID=omarchy'}
  findmnt -no FSTYPE,OPTIONS /   ->  mount: {filesystem: btrfs, opt: [matches: 'subvol=/@($|,)']}
  findmnt -no FSTYPE /boot       ->  mount: {mount: /boot, filesystem: vfat}
  cat /proc/cmdline              ->  file: {contains: [rootflags=subvol=@, rootfstype=btrfs]}

The one that stays `command:` is the ESP check: it needs `sudo -n test -f` because the
installed ESP is mode 0700, and `file:` cannot elevate.

The subvolume matcher is an ANCHORED REGEX, not `contains`. `mount:` matches against the
whole comma-joined option string, so `contains: subvol=/@` also matches `subvol=/@home`,
`/@log` and `/@pkg` — the same trap fixed in the ISO bed in #8.

## Why this was withdrawn from #8

The bed could not run at all: its guest never booted. That is fixed in
opencharly/charly#502 — charly's limine.conf wrote a depth-1 entry that limine-entry-tool
then nested its own UKI entry under, converting charly's bootable entry into an unbootable
branch.

WarningsFatal: false}`, so they are reported, not fatal. All three ERRORS are allowlisted by
name, including `limine-esp-not-mounted-in-chroot` from `opencharly/plugin-check#11`.
