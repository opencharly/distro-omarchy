# 2026.246.0545 — docs(skill): omarchy-eval — never mock anything, honest tier semantics

## Summary

Correct the `omarchy-eval` skill (the agent-facing omarchy PR evaluation procedure) to match reality and the new eval guidelines.

**The problem (full RCA in opencharly/eval-omarchy's plan):** the skill claimed the checks assert *"the resulting SYSTEM STATE (charly consequence checks), not upstream's mocked call sequences — strictly stronger"* — but the pod-tier implementation substituted mocked external tools (cardwire/supergfxd, df/findmnt, flatpak profile) and reports claimed live behavior from them. A guidance collapse: the contract was never operationalized into enforceable rules.

**This change makes the skill crystal clear:**
- **The first rule: NEVER mock anything — ever.** A mocked check is not evidence; a report built on mocks is useless. A behavior that cannot be tested with the real tools of the current tier is tested on the live VM or not claimed.
- **What each tier proves (honest semantics):** the Tier-1 container proves script logic and file application with REAL tools only, never live system behavior; the Tier-2 live VM is the tier for system-behavior claims (real cardwire, real btrfs snapshots, real flatpak, real network, real desktop).
- **Routing rule:** system-behavior PRs (hardware switching, filesystem/snapshot behavior, session environment, network state, keybindings, services) MUST be evaluated on a live VM, not just the container.
- **Known-red fixture:** every PR-specific check must fail without the PR applied; general sanity checks are labeled non-PR-specific.
- **Guardrails** updated with the no-mock, known-red, and tier-scoping rules.
