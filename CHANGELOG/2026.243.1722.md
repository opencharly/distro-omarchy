### Probed before asserted — and that changed the answer

The candidate list is **not** uniformly true of a stock install, so every path was probed
read-only over `charly vm ssh` against a freshly rebuilt guest *before* an assertion was written.
Five siblings came back **absent**, and are deliberately not asserted:

```
absent  /etc/fido2                            enrolment opt-in
absent  /etc/pam.d/omarchy-lock-fingerprint   enrolment opt-in
absent  /etc/omarchy.conf                     `omarchy dev-link` opt-in
absent  /etc/sudoers.d/omarchy-dev-path       `omarchy dev-link` opt-in
absent  /etc/modprobe.d/brcmfmac.conf         Broadcom hardware
```

Asserting any of them would fail a **correct** guest.

The sixth is the instructive one: `/etc/chromium/policies/managed` **exists but holds zero
entries**, so this asserts the *directory* only. A policy-**file** assertion — which is what
`browser-policy-dir-test.sh` and `default-apps-test.sh` are really about — would also fail a
correct 4.0.1 guest, and is left out until a release ships one.

### Why values, not just existence

Where the value is the point, the value is asserted:

- **`InhibitDelayMaxSec=15`** — a delay inhibitor is a *timer*, not a promise: logind suspends
  once the window expires whether the session locked or not. The drop-in's own comment records
  that five seconds is too short when closing the lid also reconfigures displays.
- **`btrfs-overlayfs`** — what makes a snapshot bootable. Its absence would silently regress the
  snapshot claim this same bed already makes, and a bare existence check on the hooks file would
  not notice.
- **`XKBOPTIONS=terminate:ctrl_alt_bksp`** — the installer answers' keyboard choice, observable.
