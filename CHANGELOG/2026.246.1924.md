# 2026.246.1924 — feat(bed): check-omarchy-pr-vm-anchored — snapshot-anchored PR eval (runtime apply seam)

## Summary

Add `check-omarchy-pr-vm-anchored` — the snapshot-anchored twin of `check-omarchy-pr-vm` for the omarchy PR-evaluation batch loop (plan/omarchy-pr-validation-disk-link-gif.md, Phase 2).

The bed derives from the omarchy-vm template with the charly toolchain + auto-login + a golden snapshot (`snapshot: {on_finalize: golden, keep_venue: true}`). Run with `charly check run <bed> --anchor golden --keep-venue`: the golden disk is reverted before the checks (revert ≈ seconds vs fresh ISO install ≈ 20–30 min), so a batch of PR runs shares ONE golden base. The FRESH lane (no `--anchor`) provisions the golden once.

**Design constraint verified against plugin-check source (anchored.go + bed_run.go):** anchored mode SKIPS vm-create, waitReady AND deploy-add — the venue is kept from the fresh lane and the golden is reverted before the checks. Therefore a PR candy (`add_candy: omarchy-pr-<N>`) never applies in the anchored lane. The PR is applied at RUNTIME via the apply seam: a `pr-apply` check step fetches pull/<N>/head SHA-pinned and installs the changed files over the installed tree (with sudo — the guest's passwordless sudo is established at prepare-venue), a `pr-applied` check proves the file is in place, then the PR's behavior checks run.
