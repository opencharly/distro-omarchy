### Boot fixes the containerDisk bed surfaced (each MEASURED on the running VM)

The Cua containerDisk is a DIFFERENT disk from the ISO install the `omarchy-vm` template
describes — copying its fields broke the boot:

1. **`firmware: uefi-insecure` → `bios`.** Cua's own `smoke-test.sh` boots the disk with bare
   `qemu -machine q35` (BIOS/SeaBIOS), and spike S3 reproduced the full guest contract that
   way. Its limine cmdline carries NO `root=` (the initramfs resolves root itself), so under
   OVMF the guest reports an empty root and drops to a dracut emergency shell:
   `ERROR: Failed to mount '' on real root … emergency shell` (screenshot-verified).
2. **`ssh.user user` → `omarchy`.** Measured in the booted guest: `getent passwd 1000` →
   `omarchy` (home `/home/omarchy`); there is NO `user` account. charly's injected key landed in
   `/etc/ssh/authorized_keys.d/user`, which no one reads, so sshd rejected every login.
3. **`.gitignore` gains `image/`** — `charly vm build` writes the disk + seed + build stamp
   there and it was untracked-but-not-ignored (same class as the ignored `.build/`/`output/`).
4. **Matchers hardened** — no `matches: '.+'` survives; `list-tools` asserts real tool names.
